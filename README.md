# GP RACING LEGENDS: WORLD CHAMPIONSHIP

A browser motorcycle Grand Prix racing game built with Three.js. It's a static site, installable as a PWA, and single-player works offline.

**Play:** https://kob3435-bot.github.io/gp-racing-legends/

All riders, teams, manufacturers, sponsors, liveries and circuits are **fictional**.

## Features (v1)
- **Modes:** Quick Race, Championship (saved season, rider and team standings), Dream Grid (riders from every era with REAL / BALANCED / EQUAL machinery), Spectator, Rider Database, Statistics, Settings.
- **Content:** 62 riders (22 current, 5 rookies, 35 legend "prime" versions), 23 bikes from 6 manufacturers, 11 teams, 14 tracks generated from spline control points.
- **Controls:** SEMI AUTO (default: you steer and choose the line, the game handles throttle, brakes and gears), FULL ASSIST, or MANUAL (throttle, brake and gears, and you can crash).
- **Racing:** AI with personalities, slipstream, and attack/defend decisions; no rubber-banding. Tyre compounds and weather (rain helps wet specialists), 4 cameras, racing-line assist.
- **Platforms:** Keyboard, touch buttons (mobile landscape), gamepad. Graphics presets LOW–ULTRA with automatic downgrade when FPS drops.

## Controls
| Action | Keys |
|---|---|
| Steer | ← / → or A / D (touch buttons on mobile) |
| Throttle / brake (MANUAL) | W / S |
| Gear up / down (MANUAL) | Shift / Ctrl (or E / Q) |
| Camera | C |
| Racing line | L |
| Reset after crash | R |
| Pause | Esc / P |

## Development
```bash
npm install
npm run dev        # dev server
npm run build      # -> dist/ (base path /gp-racing-legends/; override with BASE_PATH=/)
npm run preview    # serves dist on http://localhost:4173/gp-racing-legends/
npm run simulate   # headless balance simulation -> balance-report.txt
npm run test:e2e   # headless Chrome QA (needs preview running; CHROME=/path/to/chrome)
npm run test:modes # Dream Grid / Spectator / Championship flows
```

## Data
Riders, bikes, teams and tracks live in `src/data/`. Rider attributes are generated by `tools/gen-riders.mjs` into `riders.json`. OVR is always computed from the attributes, never set by hand. The game AI and the balance simulator share one performance model, `src/game/perf.js`.

Deployed to GitHub Pages by `.github/workflows/deploy.yml` on every push to `main`.

## Online Championship (2 players, v4)

1. Player 1: **ONLINE CHAMPIONSHIP → CREATE ROOM**. A 5-character room code and a share link (`?room=CODE`) appear — send either to your friend.
2. Player 2: open the link (auto-joins) or **ONLINE CHAMPIONSHIP → JOIN** and type the code.
3. Both pick a different rider; the host sets rounds (full calendar or 2/4/6/10), laps per race (1/3/5/10/realistic/custom), weather and AI difficulty. Both press **READY**, host presses **START SEASON**.
4. In the online hub the host starts each round; lights are clock-synced so both go green together. 22 riders: 2 humans + 20 AI.
5. The season is saved on both devices. If anyone drops, AI rides their bike for the rest of the race; reopen the game → ONLINE CHAMPIONSHIP → **RESUME SEASON** (same code) to reconnect.

**Architecture:** WebRTC DataChannels via PeerJS (bundled) using the free public PeerJS broker for signaling only; public STUN (Google, Cloudflare) plus the free public PeerJS TURN relay as a best-effort fallback. Host-authoritative AI, start lights, finish order and points; each player's own bike is simulated locally (zero input delay) and streamed at 30 Hz on an unreliable channel, AI at 20 Hz; remote bikes render from an adaptive jitter buffer (interpolation + short extrapolation + smoothing).

**Limitations:** no dedicated TURN server — on very strict NATs/firewalls (some corporate or carrier networks) the direct link can fail; the game then shows a clear error (try another Wi-Fi or a phone hotspot). Signaling depends on the free PeerJS cloud broker being up. Mid-race rejoin is not possible (the AI finishes that race; you rejoin for the next round).

Tests: `node tests/online.mjs [url] [--lag] [--local]` (two browser contexts; `--lag` adds 150-200 ms latency and 5 % packet loss).
